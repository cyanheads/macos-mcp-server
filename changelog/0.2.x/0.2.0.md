# 0.2.0 — 2026-09-24

Calls that omit an action's required argument, or pass an out-of-range number, now fail as `-32602` `invalid_arguments` before anything runs; some of them used to succeed.

## Changed

- **Per-action required arguments** are declared once per tool with `withActionRequirements` (`src/mcp-server/tools/action-requirements.ts`), rejected when missing or `""`, and advertised as a root `anyOf` in `inputSchema` ([#11](https://github.com/cyanheads/macos-mcp-server/issues/11)). Newly rejected:
  - `macos_control_volume` `set` without `level` or `muted`
  - `macos_control_appearance` and `macos_manage_focus` `set` without `mode`
  - `macos_manage_apps` `launch` without `app_name` or `bundle_id`; `quit`/`force_quit`/`hide`/`show` without `app_name`
  - `macos_manage_windows` `focus`/`minimize`/`fullscreen`/`close` without `app_name` or `window_title`; `move` also without `x`/`y`, `resize` without `width`/`height`, `move_resize` without all four
  - `macos_control_audio` `switch_output`/`switch_input` without `device`
  - `macos_manage_finder` `reveal`/`open_with`/`trash` without `path`
  - `macos_manage_displays` `apply_layout` without `layout_name`
  - `macos_take_screenshot` `target=region` without `region`, `target=window` without `app_name`
- **Numeric bounds**: `macos_take_screenshot` `display_index` must be an integer ≥ 0 and `region.width`/`region.height` greater than 0; `macos_manage_windows` `width`/`height` must be greater than 0. Checked on every call, including an action or target that ignores the field (`display_index: -1` with `target=screen`, `width: 0` with `focus`)
- **`macos_control_volume`** and **`macos_control_appearance`** echo `action` in their output
- **`macos_manage_apps` `force_quit`/`hide`/`show`** resolve `app_name` as an application, not a System Events process name, so a background-only process with no application of that name (`universalaccessd`) now returns `not_running`
- **`macos_manage_apps`**: `frontmost` with no app in front returns the new `no_frontmost_app` reason (was `app_not_found`, which now means only a `launch` of an uninstalled app)
- **`macos_manage_finder`** description states that `frontmost_path`, `get_selection`, and `trash` require Automation > Finder, and that `open_with` without `app_name` uses the file's default app

## Fixed

- **`macos_manage_apps` `quit`** reported success for an app that wasn't running; `quit`, `force_quit`, `hide`, and `show` now check `application "X" is running`, which also finds apps whose process name differs (`Visual Studio Code` → `Code`), and return `not_running` ([#7](https://github.com/cyanheads/macos-mcp-server/issues/7))
- **`macos_control_volume` `set`** with neither `level` nor `muted` no longer reports a no-op as success ([#8](https://github.com/cyanheads/macos-mcp-server/issues/8))
- **`macos_manage_finder` `trash` / `open_with`** on a nonexistent path return `path_not_found` instead of `-32603`; Finder refusing an existing item is the new `trash_refused`, and an unknown `open_with` app is `app_not_found` ([#9](https://github.com/cyanheads/macos-mcp-server/issues/9))
- **`accessibility_required`** now reaches the wire: `OsascriptService` denials carry the reason with a hint naming the pane actually denied (Accessibility, or Automation > the target app), and `macos_manage_windows` passes a denial through instead of reporting `window_not_found` ([#14](https://github.com/cyanheads/macos-mcp-server/issues/14))
- **Denial detection** no longer treats a bare `-1719` ("Invalid index") or `-25212` as a permission error, so `macos_manage_finder` `get_selection` with no Finder window returns `finder_not_open` rather than `accessibility_required`, and `macos_manage_apps` `frontmost` with no frontmost process returns `no_frontmost_app`
- **Subprocess errors** carry the program's own error text — the AppleScript `execution error: … (N)` line for osascript — never the `Command failed: <cmd> <args>` line or `data.script`; the script source goes to `ctx.log.debug` only ([#16](https://github.com/cyanheads/macos-mcp-server/issues/16))
- **`macos_manage_apps` `launch`** with an unknown `bundle_id` returns `app_not_found`

## Dependencies

- `@types/node` `^26.6.1` → `^26.6.2` (dev)
