# 0.4.0 — 2026-10-29

## Added

- **`macos_control_music`** (#5): play, pause, stop, skip, play a playlist by exact name, set shuffle or repeat, or read what Music is playing. Every action returns the state Music reports afterward. Requires Automation > Music; a closed Music is launched only by `play` and `play_playlist`.
- **`macos_check_permissions`** gains `automation_music` and `unknown_reasons.automation_music`, read from the same prompt-free probe as Automation > Finder (#5).
- **`macos_control_system` `lock`** returns `method` (`keystroke` or `screen_saver`) and declares the `accessibility_required` error (#38).
- **`skills/macos-guide`** is published to connected agents as `skill://macos-guide/SKILL.md`, covering permission denials, identifier sources, and confirm-before-destructive gates.

## Changed

- **`macos_control_system` `lock`** starts the screen saver only when the ⌃⌘Q keystroke is denied (Accessibility or Automation > System Events); a keystroke `Timeout` or any other failure propagates without a fallback. The screen saver locks the session only when "Require password after screen saver begins or display is turned off" is set to Immediately (#38).
- **`destructiveHint`** is `true` on `macos_manage_apps`, `macos_manage_windows`, `macos_manage_finder`, and `macos_take_screenshot`, and `false` on every other write tool; it was unset, which clients read as `true` (#39).
- **Server `instructions`** and the package description now cover Music, and state that `macos_check_permissions` cannot see Automation > System Events.

## Fixed

- **`macos_control_system` `lock`** no longer ends the screen saver it started: the fallback runs detached with no timeout. A failed fallback is `accessibility_required` with the denied pane's hint instead of a reasonless `forbidden` (#38).
- **`not allowed to send keystrokes (1002)`** from System Events classifies as `accessibility_required` instead of a generic `osascript failed` (#38).
