# 0.5.0 — 2026-11-21

## Added

- **`macos_control_music` `list_playlists`** returns `playlists`, every playlist name in Music's order, duplicates included; `playlist_not_found` recovery points to it. With Music closed it returns `running: false` and leaves Music closed. ([#44](https://github.com/cyanheads/macos-mcp-server/issues/44))
- **`macos_manage_focus` `list`** returns `modes`, each configured Focus's `name` and `identifier`, the names `set` takes; without Full Disk Access it fails `full_disk_access_required`. `get` adds `mode_name`. ([#43](https://github.com/cyanheads/macos-mcp-server/issues/43))
- **`macos_manage_displays` `list` and `macos://displays`** return `scale_factor` (pixels per point) for each display, absent when the NSScreen read fails. ([#46](https://github.com/cyanheads/macos-mcp-server/issues/46))
- **`macos_check_permissions`** returns `automation_system_events` and `unknown_reasons.automation_system_events`; it reads `null` while System Events is not running, so it answers right after an app, window, appearance, or lock call. ([#47](https://github.com/cyanheads/macos-mcp-server/issues/47))
- **`macos_manage_apps` `list`** returns `app_name`, the name `quit`, `force_quit`, `hide`, and `show` take, `null` for an app with no `.app` bundle. ([#48](https://github.com/cyanheads/macos-mcp-server/issues/48))

## Changed

- **Calls that 0.4.0 answered now fail:** with `MACOS_SCREENSHOT_DIR` unset, `macos_take_screenshot` accepts a path into a symlinked `~/Desktop`'s target folder only when the path is written under `~/Desktop`. To write there another way, pass `~/Desktop/<name>.png` or set `MACOS_SCREENSHOT_DIR` to that folder. ([#42](https://github.com/cyanheads/macos-mcp-server/issues/42))
- **`macos_manage_apps` `list`** reads NSWorkspace instead of System Events, so it needs no permission and shows no consent dialog. It lists the apps with a Dock icon. ([#48](https://github.com/cyanheads/macos-mcp-server/issues/48))
- **`MACOS_SCREENSHOT_DIR`** is described, in `server.json`, `manifest.json`, and the config schema, as also an allowed directory for a custom `path`. ([#42](https://github.com/cyanheads/macos-mcp-server/issues/42))

## Fixed

- **`macos_take_screenshot` `target=screen`, `display`, and `region`** with Screen Recording denied fail `screen_recording_required` instead of returning an image without app windows. When the check cannot tell, they capture and return `notice`, as `window` does. ([#41](https://github.com/cyanheads/macos-mcp-server/issues/41))
- **`macos_take_screenshot` with a `path`** no longer resolves `~/Desktop` first, which under Bun raised the Desktop privacy prompt and blocked the call. `EPERM` on the capture's directory fails `path_not_writable` with a Files & Folders hint. ([#42](https://github.com/cyanheads/macos-mcp-server/issues/42))
- **`macos_manage_focus` `get`** returns `unknown` naming Full Disk Access when macOS refuses the read, and `inactive` carries a `notice` that a Focus started by its schedule or another trigger is not recorded. The CommCenter `defaults` probe is removed. ([#43](https://github.com/cyanheads/macos-mcp-server/issues/43))
- **`macos_control_audio` `switch_output` and `switch_input`** with a name that two or more devices fit now fail `device_ambiguous` instead of switching to the first listed. A name identical to one device, or equal to one ignoring case, wins over devices that merely contain it. ([#45](https://github.com/cyanheads/macos-mcp-server/issues/45))
- **Window bounds and screenshot `region`** are described as points in global display coordinates, not pixels; screenshot `width` and `height` are pixels, the captured points × `scale_factor`. ([#46](https://github.com/cyanheads/macos-mcp-server/issues/46))
- **Screen Recording hints** name the pane "Screen & System Audio Recording (Screen Recording on older macOS)".
